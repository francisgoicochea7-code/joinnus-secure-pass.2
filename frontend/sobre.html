Sobre Joinnus Secure Pass

“Verifica, transfiere y protege tus entradas digitales.” Prototipo académico de seguridad para entradas digitales.

Comprobando conexión…

Problema

Reventa informal, duplicación de entradas y estafas relacionadas con códigos QR.

Una misma entrada puede ofrecerse a varias personas. Sólo la primera que presenta el QR logra ingresar; el resto pierde su dinero.

Propuesta

Implementar:

  • API de consulta de estado.
  • QR dinámicos.
  • Transferencia segura.
  • Trazabilidad de entradas.

Objetivo

Mejorar la seguridad de las entradas digitales y brindar mayor control sobre su uso y transferencia.

Reducir el riesgo de duplicación, permitir una transferencia legítima y dejar registro de cada operación.

Este proyecto es un prototipo académico. Los datos (nombres, DNI, correos y eventos) son completamente ficticios. La autenticación de usuarios y los pagos siguen siendo simulados.

Arquitectura del proyecto

Con Docker el sistema se reparte en tres contenedores que se comunican por la red interna jsp_net.

1
Navegador
Páginas estáticas servidas por nginx (contenedor frontend)
2
Cliente HTTP (fetch)
js/cliente-api.js —js/api.js decide entre API y localStorage
3
API REST
Express en el contenedor backend (puerto 3000)
4
MySQL 8
Tablas usuarios, eventos, entradas, transferencias, historial y tokens_qr

Endpoints de la API

GET /api/healthEstado del servicio
GET /api/entradas/:codigoConsultar entrada
GET /api/verificar/:codigoVerificar estado
POST /api/entradas/:codigo/qrGenerar token QR
POST /api/qr/validarValidar token
POST .../transferirTransferir entrada
GET .../historialObtener historial

La misma interfaz (SecurePassAPI) también funciona sin Docker, usando localStorage.

¿Qué es real y qué está simulado?

Funciona de verdad

  • Códigos QR reales generados en el navegador (Reed-Solomon, ISO/IEC 18004).
  • Rotación del token cada 15 segundos con contador regresivo.
  • Firma HMAC-SHA256 de los tokens en el servidor.
  • Validaciones de DNI, correo, nombre y límite de precio (cliente y servidor).
  • Persistencia real en MySQL (o localStorage sin Docker).
  • Historial completo de trazabilidad con exportación a CSV.

Simulado en el prototipo

  • Autenticación de usuarios y sesión segura (el usuario demo está fijado por variable de entorno).
  • Lector físico de QR y control de acceso en la puerta del evento.
  • Pagos reales y validación de identidad contra RENIEC.
  • Cifrado en reposo de los datos personales.
  • Escalabilidad y alta disponibilidad (una sola instancia de cada servicio).

Ciclo de vida de una entrada

1. Emisión

La entrada se crea con estado Válido

2. QR dinámico

Token temporal que rota cada 15 s

3. Transferencia

Cambio de titular con control de precio

4. Uso único

Tras el ingreso pasa a Usado

Cómo ejecutar el proyecto

  1. Abre una terminal en la carpeta joinnus-secure-pass/.
  2. Ejecuta docker compose up --build.
  3. Entra en http://localhost:8080 desde el navegador.

Sin Docker también funciona: abre frontend/index.html con doble clic y el prototipo usará localStorage.
