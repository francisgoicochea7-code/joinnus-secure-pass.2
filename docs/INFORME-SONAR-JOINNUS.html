3. Metodología y alcance

3.1 Qué revisa SonarQube

SonarQube es un analizador estático: lee el código sin ejecutarlo y busca patrones de riesgo, defectos de fiabilidad, problemas de mantenibilidad, duplicación y malas prácticas. No sustituye a las pruebas funcionales ni a un escaneo dinámico como OWASP ZAP; los tres enfoques se complementan.

6. Quality gate del proyecto

El gate JSP - proyecto se diseñó a medida para este prototipo. Evalúa el código nuevo y contempla:

  • bugs,
  • vulnerabilidades,
  • security hotspots,
  • code smells,
  • duplicación.

No exige cobertura porque la suite actual es un script propio sin instrumentación. Forzar un porcentaje de cobertura habría producido un gate engañoso: se habría cumplido o fallado por una métrica que el proyecto no genera.

8. Limitaciones del análisis

  • Es análisis estático. No prueba la aplicación en ejecución ni reemplaza un escaneo dinámico. Para eso se usó OWASP ZAP en local.
  • No mide cobertura. La suite no está instrumentada; decir “0 % de cobertura” sería incorrecto, y forzar una métrica artificial no aportaría valor.
  • Edición Community. SonarQube Community no ejecuta todos los análisis de flujo para inyecciones; por eso el proyecto se complementa con revisión manual y con ZAP.
  • El gate evalúa código nuevo. En este caso el código general también está limpio, así que la lectura es consistente.
  • La captura visual está pendiente de actualizar después del commit, para eliminar el aviso de SCM.
